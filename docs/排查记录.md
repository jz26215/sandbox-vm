# 排查记录（踩过的坑）

> 本文主要由 AI 生成，仅作思路参考。都是作者环境里实际遇到的情况。

## 1. Docker Hub 连不上，拉镜像超时

- 原因：直连 Docker Hub 不通。
- 做法：`setup/4-设置Docker代理.sh` 给 dockerd 和 Docker 客户端都配上 Windows 上的代理。代理软件要开「允许局域网连接」。
- 坑：换了基础镜像以后，**BuildKit 解析基础镜像时不走 dockerd 的代理**，构建会超时。`sb.sh up` 现在会先用 `docker pull` 把缺的基础镜像拉下来（`pullbase`）。

## 2. proxy 容器起不来：`Exited (128)`，`Address already in use`

- 原因：proxy 停着的时候 box 重启，box 被分到了 proxy 的固定 IP `172.30.0.2`。
- 做法：box 也固定 IP，`172.30.0.3`。

## 3. 误以为防火墙有漏洞：proxy「能直连」example.org

- 现象：装好防火墙后，在 proxy 容器里 `wget http://example.org` 还能成功。
- 原因：`~/.docker/config.json` 里的 `proxies` 会被 Docker **自动注入成每个容器的 `HTTP_PROXY` 环境变量**，wget 实际走的是上游代理，不是直连。
- 做法：测试直连前先 `unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY`。去掉以后直连被拒（Connection refused），说明防火墙是有效的。自检和断网测试脚本都已经按这个改过。

## 4. VS Code 每次连接卡约 4 分钟（没解决）

时间线（沙箱这边用 `docker events` 和进程列表记录）：

1. 插件在 WSL 里建好进容器的常驻通道（`docker exec -i ... /bin/sh`），转发程序几秒内就启动好了。
2. 接下来**正好 240 秒**什么都没发生。
3. 插件改用一条新的 `docker exec` 直接转发，马上就连上了。容器里的 VS Code 服务端一收到连接，1 秒内就准备好。

Windows 那一侧的日志：第一次连接通道一建立就断了，报 `unexpected end of parent stream` / `stream is closed`，出在插件的 `remoteExec`。之后等满 240000 ms 超时才重试。

已经排除的原因：
- 沙箱里有残留的 VS Code 进程：清理以后照样慢
- 插件版本旧：插件是当天装的最新版；日志里的 `navigator is now a global` 报错是 VS Code 的通用提示
- WSL 的「localhost 代理」提醒混进数据通道：实测这条提醒只写到 stderr
- Windows 到 WSL 多转了一道：从 WSL 窗口里附加也一样慢
- 沙箱资源不够：CPU 0.3%，内存 740M / 2G

还不清楚的：第一次连接为什么会断。有一次在 WSL 刚重启后很快就连上了，是不是和这个有关还没确认。

## 5. VS Code 设置管不住 X11 图形通道

- 现象：设了 `dev.containers.mountWaylandSocket=false` 和 `forwardWSLServices=false`，容器里还是有 `DISPLAY=:0` 和 `/tmp/.X11-unix/X0`。WSL 的图形界面剪贴板和 Windows 是同步的。
- 做法：compose 给 box 挂一个只读的空目录到 `/tmp/.X11-unix`，VS Code 就建不了这条通道。之后 VS Code 照常能连。

## 6. 检查脚本认不出 VS Code 终端

VS Code 终端里的 bash 带了 `--init-file /sandbox/.vscode-server/...`（终端集成脚本），按路径判断时会被当成 VS Code 自己的进程。改成按环境变量 `TERM_PROGRAM=vscode` 判断。

## 7. 普通 VS Code 窗口里看不到容器

Docker 装在 WSL 里，Windows 这边的 VS Code 直接找不到它。要先连 WSL 窗口，或者用 `code --folder-uri vscode-remote://attached-container+<十六进制>/sandbox` 直接打开（见 `windows/VSCode打开沙箱.bat`）。

## 8. 其它

- npm 全局安装 Claude Code / Codex 偶尔会卡住没输出，Ctrl+C 后重跑就好。
- Debian 不允许 pip 直接往系统里装（PEP 668），在项目里建 venv：`python3 -m venv .venv && . .venv/bin/activate`。
- WSL 的主机 IP 重启后可能变化，所以上游代理用 `auto:<端口>`，每次启动自动计算。
