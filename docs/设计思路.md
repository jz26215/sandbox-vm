# 设计思路

> 本文主要由 AI 生成，仅作思路参考。

## 1. 为什么用 WSL2 + Docker

- WSL2 本身就是一个轻量的 Hyper-V 虚拟机，Windows 家庭版也能用，开机快，占资源少。
- Docker 负责把「沙箱」和「代理」分成两个互相隔离的容器，网络和文件都能精确控制。
- 代价：容器和 WSL 共用一个 Linux 内核，隔离强度不如独立虚拟机。WSL 默认能看到 Windows 盘，`setup/3-可选-加固WSL.sh` 可以关掉，但会影响这个 WSL 的其它用法。

## 2. 为什么分成 box 和 proxy 两个容器

- box（跑 AI 工具的容器）**只接在 `internal: true` 的网络上**，这个网络没有任何外网路由。就算程序不理会 `HTTP_PROXY` 设置、自己直接连外网，也连不出去。
- box 的 DNS 设成 `127.0.0.1`，等于不给 DNS，防止通过 DNS 查询往外传数据。所有域名解析都交给 proxy 去做。
- proxy 同时接在 internal 网络和一个普通网络（egress）上，是 box 唯一的出口。

## 3. 为什么用 tinyproxy

- 小，配置简单：`FilterDefaultDeny Yes` 加上白名单文件，就是默认全部拒绝。
- 按 CONNECT 请求里的主机名过滤，用 `ConnectPort` 限制 HTTPS 端口。
- 缺点：不解 TLS，也不核对 SNI 和 CONNECT 主机名是否一致；`ConnectPort` 不管普通 HTTP。想更严格可以换 Squid（SNI peek-and-splice）或 Envoy。

## 4. 为什么还要主机防火墙（sandbox-fw）

proxy 容器本身是能上外网的。「只走上游代理、上游断了不回落直连」原本只是 tinyproxy 的软件行为，网络层面并没有堵死。所以在 WSL 里加了一层 iptables：

- 给 egress 网络固定网卡名 `sbx-egress`（compose 里的 `com.docker.network.bridge.name`），规则按网卡名匹配。
- 规则写在 Docker 专门留给用户的 `DOCKER-USER` 链里：从 `sbx-egress` 出去的流量只放行「上游代理 IP + 端口」，其余全部 REJECT。
- IPv6：上游只是 IPv4，所以 `sbx-egress` 的 IPv6 全部拒绝。
- INPUT 链：不准 proxy 主动连 WSL 本机，回包放行。
- 改规则时先在最前面插一条「全部拒绝」，改完再撤掉，中间没有空档。算不出上游代理地址时保持全部拒绝。
- 做成 systemd 服务，`Before=docker.service`，开机时比 Docker 先生效。
- `UPSTREAM_PROXY=auto:<端口>` 时自动取 WSL 的默认网关，也就是 Windows 主机 IP。`./sb.sh upstream` 改上游时会自动重载规则。
- 断网测试会临时把上游改成 `127.0.0.1:1`，这时 sb.sh 跳过重载，不用每次都输密码。

## 5. 为什么根文件系统只读、工具装在镜像里

- 运行时改不了系统，AI 工具也不能给自己装东西或者改自己。
- Claude Code 和 Codex 用 npm 装在镜像里，关掉自动更新；升级就是重建镜像（`./sb.sh up`）。
- `HOME=/sandbox`，登录信息（`.claude*`、`.codex`）存在 `data/` 里，重建镜像也不会丢。
- 有 pip、venv、gcc、make。Debian 不允许 pip 直接往系统里装（PEP 668），需要在项目里建 venv。
- `/tmp` 用 512M 的内存盘并允许执行，VS Code 服务端安装时要用。

## 6. 数据放在哪

- `data/` 放在 WSL 自己的磁盘里（`~/sandbox-vm/data`），不放在 `/mnt/c`、`/mnt/d`：一是速度快，二是和 Windows 盘分开。
- 在 Windows 里通过 `\\wsl$\Ubuntu\home\<用户名>\sandbox-vm\data` 访问，`windows/打开沙箱文件夹.bat` 可以直接打开。
- 从沙箱里拿出来的程序和脚本，先看懂再在 Windows 上运行。

## 7. 为什么给两个容器都固定 IP

proxy 的固定 IP 是 `172.30.0.2`。早期 box 没有固定 IP，proxy 停着的时候 box 一重启，就可能被分到 `172.30.0.2`，之后 proxy 就起不来了（`Address already in use`）。现在 box 固定为 `172.30.0.3`。

## 8. 时区和参考时钟

- 沙箱时区就是容器的 `TZ` 环境变量，`./sb.sh tz <时区>` 修改。
- `./sb.sh clock` 只是显示另一个时区的当前时间，以及那里现在是不是工作时段，不改沙箱。
- 这两个功能都不是为了隐藏真实地区。

## 9. 威胁模型

**防：**
- AI 工具误操作或执行恶意命令，删改沙箱以外的文件
- 未经允许连到白名单以外的地址；代理断了以后偷偷直连
- 读取宿主机上的凭据，比如 SSH 密钥、git 账号、Docker 登录
- 通过 DNS 往外传数据（box 这一层）

**不防：**
- 利用白名单域名本身外传数据，比如往 GitHub 推代码
- 内核漏洞导致的容器逃逸
- VS Code 插件层面的通道：剪贴板、打开浏览器、申请 VS Code 账号
- 资源占用、时间信息之类的侧信道
